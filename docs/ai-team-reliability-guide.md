# AI 团队可靠执行知识文档

本文说明当前项目如何让主 Agent、子 Agent 和工作区工具组成一个可控制、可恢复、可观察的 AI 团队。重点不是让 Agent 反复尝试，而是在明确边界内完成任务，并在异常发生时安全停止。

## 1. 完整执行流程

```text
用户任务
  ↓
主管 Agent 理解任务并拆分子任务
  ↓
检查依赖关系、权限、预算与并发限制
  ↓
调度固定子 Agent 或动态子 Agent
  ↓
只读任务：允许受控自动重试
写文件/运行命令：审批 + 幂等执行，不盲目重试
  ↓
记录任务耗时、尝试次数、估算 Token 和执行事件
  ↓
汇总结果并返回用户
```

## 2. 任务级预算统计

任务级预算用于回答以下问题：

- 一个子任务输入和输出了多少内容？
- 大约消耗了多少 Token？
- 执行了几次？
- 总共耗时多久？
- 最终是成功、失败还是被中断？

当前项目将每个子任务的输入字符数、输出字符数、估算 Token、尝试次数、耗时和状态写入 SQLite 的 `agent_task_metrics` 表。

Token 数量目前采用字符数估算，适合做成本趋势和异常检测，但不等于模型供应商返回的精确计费 Token。后续可以在模型响应包含 usage 时，用真实 usage 替换估算值。

## 3. 自动重试策略

### 3.1 最大尝试次数

当前策略是：

```text
首次执行 1 次 + 最多自动重试 4 次 = 总共最多尝试 5 次
```

第 5 次仍然失败时，任务立即中断，并返回：

```text
任务连续失败 5 次，已自动中断，避免继续重复执行。
```

这样可以避免网络异常、服务限流或模型故障造成无限循环、Token 浪费和重复任务。

### 3.2 可以重试的错误

只有通常具有临时性的错误才会自动重试：

- HTTP 429 或服务限流。
- HTTP 5xx 服务端错误。
- 临时网络失败。
- Socket 断开。
- `ECONNRESET`、`ECONNREFUSED`、`ETIMEDOUT`。
- `fetch failed` 等短暂连接问题。

等待时间采用指数退避并加入少量随机抖动，避免多个子 Agent 同时再次请求服务：

```text
第 1 次重试：约 400ms
第 2 次重试：约 800ms
第 3 次重试：约 1600ms
第 4 次重试：约 3200ms
```

### 3.3 不允许自动重试的错误

以下错误会立即停止，不会消耗剩余重试次数：

- API Key 错误、401、403 等认证或权限问题。
- 用户拒绝审批。
- 文件版本冲突。
- 用户主动停止或取消任务。
- 已超时的任务。
- 可能重复产生副作用的写文件或命令执行任务。

只读咨询子 Agent 可以安全重试。执行型子 Agent 可能已经修改文件或运行命令，因此不能把整个执行过程重新运行；这类任务依靠幂等记录和快照恢复。

## 4. Durable Execution 与幂等

Durable Execution 表示任务状态会被持久化，而不是只存在于当前 Node.js 进程中。程序重启后，可以判断某个操作是否已经完成。

幂等表示同一个任务被重复提交时，不会重复产生相同副作用。例如已经成功写入文件的工具调用，应复用上一次结果，而不是再次写入。

二者分工如下：

| 能力 | 解决的问题 |
| --- | --- |
| 自动重试 | 临时网络或模型服务错误 |
| Durable Execution | 进程中断后恢复任务状态 |
| 幂等 | 防止同一个副作用操作重复执行 |
| 文件快照 | 修改错误后查看差异或回退 |

## 5. 文件冲突处理

Agent 读取文件时会得到内容哈希。写入前再次比较哈希，可以判断文件是否在此期间被用户、IDE 或另一个 Agent 修改。

发现冲突时不会强制覆盖，用户可以：

- **保留当前文件**：放弃 Agent 的待写内容。
- **重新读取后继续**：让 Agent 基于最新内容重新生成修改。

冲突记录会写入数据库，便于刷新页面或重启后继续处理。

## 6. 命令产生的文件快照

运行命令也可能修改文件，例如格式化、代码生成、构建脚本或测试更新快照。因此项目会：

1. 在命令执行前扫描工作区文件。
2. 执行经过审批的命令。
3. 命令结束后再次扫描。
4. 找出新增、修改和删除的文件。
5. 保存修改前快照、修改后哈希和文件活动记录。
6. 在对话中提供 Diff 与安全回退能力。

扫描会忽略 `.git`、`.env`、`node_modules`、`dist`、`data`、`.next` 和 `coverage` 等目录，避免读取敏感内容或大型构建产物。

## 7. 可观测性

可观测性不是把 Agent 的内部思考展示给用户，而是记录可用于排错的结构化事件：

- 子任务开始、成功和失败。
- 自动重试及重试次数。
- 文件写入和替换。
- 命令执行及其修改文件数量。
- 文件冲突。
- 回退成功或回退冲突。

事件保存在 `agent_observability_events` 表。开发调试可以通过以下接口读取指定轮次的数据：

```http
GET /api/observability/turn?threadId=...&userId=...&turnId=...
```

这些信息属于开发诊断数据，不应直接混入普通用户的聊天回答。

## 8. 失败隔离与边界

多个子 Agent 并行执行时，一个子任务失败不应自动污染其他任务。调度器会根据任务依赖关系处理结果：

- 没有依赖关系的任务可以并行执行。
- 依赖任务失败后，下游任务被阻止，不再浪费模型调用。
- 文件写入范围由工作区授权路径限制。
- 子 Agent 只能使用主管分配的工具、Skill 和上下文。
- 冲突、审批拒绝和用户中止会立即打断对应执行链路。

## 9. 测试与验证

专项验证覆盖：

- Token 预算估算。
- 临时错误自动重试。
- 连续失败恰好尝试 5 次后中断。
- 文件冲突不自动重试。
- 子任务 DAG 循环依赖检测。
- 文件内容哈希。
- 命令前后工作区扫描。
- 忽略目录与 Buffer 比较。

运行命令：

```powershell
npm run agent-team:verify
npm run build
```

## 10. 当前能力边界

- Token 预算目前是估算值，不是供应商账单数据。
- 可写任务不会整轮自动重试，这是防止重复副作用的安全设计。
- 快照主要覆盖工作区普通文件，不适合保存超大二进制文件。
- 可观测性已有存储和查询接口，但未在普通用户界面展示开发者面板。
- 更复杂的多人冲突合并仍需要后续加入三方合并或可视化逐块选择。
