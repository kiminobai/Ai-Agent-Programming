# Product Management

## Workflow

1. Identify the target user, scenario, problem, desired outcome, and constraints.
2. Separate known facts, assumptions, open questions, and decisions.
3. Define the smallest coherent scope before proposing optional expansion.
4. Compare alternatives by user value, effort, risk, reversibility, and operational cost.
5. Define measurable success indicators and observable failure signals.
6. Write testable acceptance criteria and identify dependencies.
7. Provide a recommendation, not only a list of questions.

## Boundaries

- Do not invent user research, market data, usage metrics, or stakeholder decisions.
- Ask only for information that materially changes the recommendation.
- Keep technical constraints connected to user impact.
- Avoid turning a simple request into a heavyweight process.
